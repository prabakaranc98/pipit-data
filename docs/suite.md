# The reference problem suite

A fixed set of problems, each grounded in the field, that every release of Pipit is measured against. It shows
whether Pipit helps, and what is missing, release by release; its reading list is also where to learn each problem.

- **Benchmark-grounded:** an established benchmark exists. Pipit must agree with it, mechanism by mechanism.
- **Problem-grounded:** a paper documents a failure mode or a finding, or lists an open problem. Pipit must reproduce
  the documented effect with its own planted cases, at a stated cost, or measurably progress the open problem.

A problem joins only with a citable source and a documented number. Each release reruns the problems it touches and
states, in its release notes, which statuses changed.

Status: **reproduced** (Pipit's cases show the documented effect), **agrees** (matches the benchmark), **partly**,
**not yet**, **regressed** (was passing, now is not).

How the sources were read: by research agents on 2026-11-01, at abstract level or by keyword search of the full
text, never end to end by a person. The reading list has 125 entries, citing 123 sources (two papers are cited
twice), with 127 quotes, each word for word from the research draft. A script checked 135 quotes gathered for that
draft, these 127 among them, against their saved sources: 131 appear there exactly as written, and all 135 once
quote marks, dashes and spaces are evened out. A venue marked † comes only from Semantic Scholar's record.

#### 2. Three ways a calculation fails

| Reference | Link | Quote | What to learn |
|---|---|---|---|
| Khandekar et al., 2024, NeurIPS D&B | https://arxiv.org/abs/2406.12036 | “Common issues include extracting the incorrect entities, not using the correct equation or rules for a calculation task, or incorrectly performing the arithmetic for the computation.” | The draft's quote is exact; the same sentence is on the NeurIPS page. |
| Wang, Xia et al., 2025, EMNLP (oral) | https://aclanthology.org/2025.emnlp-main.548/ | “First, we clean and restructure the MedCalc-Bench dataset and propose a new step-by-step evaluation pipeline that independently assesses formula selection, entity extraction, and arithmetic computation. Under this granular framework, the accuracy of GPT-4o drops from 62.7% to 43.6%, revealing errors masked by prior evaluations.” | The split is published, using an LLM error-attributor checked by humans. G1's own contribution would be per-step answers computed by code, with no attributor to make mistakes. |
| Zheng et al., 2025, ACL (ProcessBench) | https://arxiv.org/abs/2412.06559 | “Each test case contains a step-by-step solution with error location annotated by human experts. Models are required to identify the earliest step that contains an error, or conclude that all steps are correct.” | "First wrong step" is the standard label. Label each case by its first failing stage: extract, choose formula, compute. |
| Dziri et al., 2023, NeurIPS† (Faith and Fate) | https://arxiv.org/abs/2305.18654 | “Our empirical findings suggest that transformer LLMs solve compositional tasks by reducing multi-step compositional reasoning into linearized subgraph matching, without necessarily developing systematic problem-solving skills.” | Write each calculator as a graph of steps; the failing step is then known by construction, and errors should grow with the number of steps. |
| Chen et al., 2023, TMLR (Program of Thoughts) | https://arxiv.org/abs/2211.12588 | “The computation is relegated to an external computer, which executes the generated programs to derive the answer.” | Run the same cases with code execution on and off; the difference is the arithmetic share of errors. |
| Gao et al., 2023, ICML† (PAL) | https://arxiv.org/abs/2211.10435 | “While LLMs seem to be adept at this sort of step-by-step decomposition, LLMs often make logical and arithmetic mistakes in the solution part, even when the problem is decomposed correctly.” | Supports a minimal pair, "values given" versus "values to find in the note", which isolates extraction. |

Where Pipit stands: the field knows the three error types and has split them step by step. What is open is doing it without an LLM judge, which G1's computed per-step answers address.

| Kim et al., 2026, HeaLing workshop (Linguistic Analysis for Health) | https://aclanthology.org/2026.healing-1.2/ | “Notably, all models are more easily persuaded to change their answers on clear multiple-choice questions than on ambiguous diagnostic cases.” | Flip rates depend on case type. #### 8. Explanations that hide the real reason

| Reference | Link | Quote | What to learn |
|---|---|---|---|
| Turpin et al., 2023, NeurIPS | https://arxiv.org/abs/2305.04388 | “We demonstrate that CoT explanations can be heavily influenced by adding biasing features to model inputs--e.g., by reordering the multiple-choice options in a few-shot prompt to make the answer always "(A)"--which models systematically fail to mention in their explanations.” | The planted-cue test in one line: plant a cue, check whether the answer moves, check whether the explanation mentions the cue. #### 11. Discovered failure rates overstate risk

| Reference | Link | Quote | What to learn |
|---|---|---|---|
| Brown et al., 2025, EMNLP (now titled "Adaptively profiling models with task elicitation") | https://arxiv.org/abs/2503.01986 | “Task elicitation finds hundreds of natural-language tasks -- an order of magnitude more than prior work -- where frontier models exhibit systematic failures, in domains ranging from forecasting to online harassment.” | Does not support the row: no failure-rate measurement on fresh cases; the full text reports only partial, uneven transfer to other models. Keep it as the discovery method under test. |
| Efron, 2011, Journal of the American Statistical Association | https://doi.org/10.1198/jasa.2011.tm11181 | “The largest few of the z(i)'s are likely to substantially overestimate their corresponding μ(i)'s, this being an example of selection bias, or regression to the mean. | Andrews, Kitagawa & McCloskey, 2024, Quarterly Journal of Economics 139(1):305–358 | https://doi.org/10.1093/qje/qjad043 | “Sampling error in the estimates used to guide choice leads to a winner’s curse, since we are more likely to select a given option precisely when we overestimate its effectiveness. | Dwork et al., 2015, NeurIPS† | https://arxiv.org/abs/1506.02629 | “Reusing a holdout set adaptively multiple times can easily lead to overfitting to the holdout set itself.” | Fresh cases must never feed back into the discovery loop. |

| Souly et al., 2024, NeurIPS Datasets & Benchmarks† (StrongREJECT) | https://arxiv.org/abs/2402.10260 | “Notably, we find that existing evaluation methods significantly overstate jailbreak effectiveness compared to human judgments and the StrongREJECT evaluator.” | A second route to overstatement, a lenient grader: a discovered failure needs a strict checker before it counts. |
| Jones et al., 2025, arXiv preprint (Anthropic) | https://arxiv.org/abs/2502.16797 | “We make forecasts by studying each query's elicitation probability -- the probability the query produces a target behavior -- and demonstrate that the largest observed elicitation probabilities predictably scale with the number of queries.” | The opposite risk: small tests can understate rare failures at deployment scale. Where Pipit stands: the statistics are textbook. I found no paper that measures this shrinkage for LLM failure discovery, so a measured result here would answer the field's open question, not only Pipit's.
